# v8 健康检查复核

本轮新增网页/CLI 共用的只读健康检查，补充独立监听任务真实证据。合约核心没有增加资金操作入口或改变分账算法。

| 问题 | 处理 |
|---|---|
| 把 remaining 回调次数当作原生执行费“fuel” | 展示 callback slots，费用单独读取 balance/reserves/debt |
| 合约余额为 0 但有预付储备，被错误当作无法执行 | 两者合并计算费率缓冲，欠费独立判定 |
| 静态配置的 chainId 不能证明 RPC 实际网络 | 显式查询 eth_chainId，错链先停止后续合约读取 |
| RPC 错误被误报为零资金、已恢复或正常 | 保留读取失败状态与最后确认的问题，不伪造零值 |
| 单次任务达到上限后主动退订，被当作预算故障 | observer 模式检查成功次数与订阅状态，单独返回 completed |
| 持续异常每次轮询重复提示 | 依照异常 ID 与严重度去重，成功复查后才确认恢复 |
| 健康报告意外带入原始 RPC 错误或配置内容 | 报告只保留检查标签；CLI 不输出原始端点/JSON 解析错误正文 |
| 大额授权导出精度损失 | 所有 BigInt 保持整数字符串 |
| --user 缺少地址时默默降级为平台检查 | 参数错误返回退出码 2 |
| 增加学习笔记后交付包漏带 notes/ | 将 notes/ 纳入白名单与 SHA256 清单 |
| 部署工具直接使用未声明的间接构建依赖 | 固定直接开发依赖 esbuild 0.25.12，与已安装版本一致 |

测试：98 个合约测试、33 个前端测试、格式/语法/构建检查，以及真实 observer 健康检查。证据与限制见 [TESTING.md](TESTING.md)。

依赖扫描：[完整依赖树](../deployments/npm-audit-v8.json)、[生产依赖](../deployments/npm-audit-production-v8.json)。完整树仍有 4 个 high 条目，源于一个尚无补丁的 picomatch 根公告；生产依赖为 0。没有隐瞒或忽略该公告来宣称扫描全绿。原有安全边界与下一阶段事项见 [CODE-REVIEW-v7.md](CODE-REVIEW-v7.md)。

本次是开发复核，不是独立审计。站内提示依赖页面运行，核心真实回调分账和失败桶重试仍待验收/开发。
