# PaydaySplit v9 工作台

同一套分账合约可管理多个资产的计划。进入仪表盘后，在 **Plan asset** 选择资产，从同一栏进入计划、自动化健康、收入追踪、资金模块或活动记录。

## 首次使用与付款确认

- 打开 **Quick-start guide**，选择无钱包演练或测试网设置。引导可以直接打开样例工作台、定位金额输入或运行一笔模拟收入。无钱包演示可试用固定金额、收入比例和 Aave 储蓄去向。
- 点击分账模板可预览金额和比例，确认后才替换草稿。保存前的弹窗会列出收款地址、分配顺序、金额和当前分配模式。Aave 适配器的创建和启用也会分别显示后续步骤。
- 要在瀑布中按固定金额储蓄，在相应行选择 **Aave V3 supply**，填写 **Fixed amount**，并把百分比设为零。按行内提示创建适配器、启用供给，再保存分账规则。额度、余额、顺序和限额会影响实付。
- Aave 的供给利率随市场变化，aToken 进入自己的钱包。演示使用样例，本地 Anvil 使用模拟池。使用支持的公开测试网资产前，核对部署配置中的资金池地址。 [Aave V3 供给说明](https://aave.com/docs/aave-v3/markets/supply)
- 首页和工作台都可以点 **Connect wallet** 选择浏览器钱包。连接后点导航栏里的地址可查看网络、复制地址或断开。演示和未配置部署的工作台只读取账户地址与当前网络。打开已验证的测试网部署后，连接时会提示切换到对应网络，再读取该账户的链上分账计划。浏览器钱包撤回站点授权时可用 **Update wallet access** 恢复。
- 如果已有部署，可在工作台或钱包详情里点 **Open testnet workspace**，选择部署 JSON 或粘贴内容。页面通过公共 RPC 检查网络、来源和回调地址，并确认合约可读取分账和代币信息。验证通过后，配置保存在当前标签页。此前保存的配置需要重新导入。选择 **Use bundled deployment** 可恢复打包配置。
- 测试网工作台显示钱包、分账、支出权限和自动化四步状态。**Check automation** 会直接检查当前钱包已保存的规则、费用和订阅。余额为零且未设置保留金额时，仍可开始第一笔测试收入。
- 工作台根据当前钱包、已保存的去向、支出授权和自动化检查提示下一步。修改草稿时仍会提示链上沿用已保存的规则。演示模式可直接运行一笔样例，页面会定位到对应的记录。
- 更改授权前可核对旧额度、目标额度及支出合约。暂停和撤销是两个独立操作。暂停保留草稿和额度，撤销将该代币的授权归零并保留分账规则。付款历史区分样例收入、来源收入分账与新手动付款。
- 新手动付款按 **Review → Wallet → Receipt** 显示进度。签名前重新读链上预演，报价变化时要求再次审阅。钱包广播后可按交易哈希查询，页面拿到回执才显示实际分账和留存。补发已有转账从 **Income trace** 进入。
- Circle 测试归集的销毁和铸造按钮会分别发起来源与目标测试网切换，并复核钱包账户后进入对应步骤。

## 前端与合约同步

- 余额、授权、已保存的规则和支出设置从同一目标链区块读取。收到交易确认后，刷新会包含该交易所在区块。RPC 尚未同步时，工作台提示重试。
- 更改授权前读取当前链上额度。替换非零额度时，先在钱包签署清零并核对链上结果，再签署新额度。确认后显示实际可用额度。
- 领取测试收入后，可以点 **Trace this income** 查看这笔收入。来源交易确认后，页面继续跟踪回调，同时可以继续使用工作台。
- 本地回调监听按资产和账户读取已保存的规则，支持由任意本地测试钱包完成同一流程。独立浏览器实测第二个钱包领取 1,000 dUSDC 后自动分出 700，留存 300。重复处理后的新增回调数为 0。[双钱包本地验收记录](integration/browser-local-evidence.json)
- 合约接口由 `node web/script/contract-abi.mjs` 从 Foundry 构建产物生成，GitHub CI 检查接口是否同步。

- USDC 与 WETH 各有独立规则、授权、余额、收款目的地和记录。WETH 模板默认采用百分比，预演金额为 0.1 WETH。公共链保存模板前，需要用自己的地址替换示例收款地址。
- 连接时核对钱包账户、网络、分账合约代码与代币精度。切换钱包账户或网络会使当前计划断开并清除旧结果，跨链来源哈希可在页面中继续使用。切换资产后重新连接以读取该资产的计划。自定义标签按钱包、链和资产保存，先前版本的共享标签需重新填写。
- 用收入交易哈希打开 **Income trace**。初始分出与留存仍对应原回调。补付按来源交易及日志序号关联，成功的补付计入更新后的金额，其余状态会单独显示。追踪验证覆盖当前链最近最多 5,001 个区块，超出窗口或读取失败时页面会提示。
- 活动页的 CSV 记录首次链上结果，包含链、代币、来源交易、日志序号和记录类型。导出使用原始精度，并区分模拟和链上记录。后续补付明细可从该笔收入导出追踪 JSON。CSV 导入每行一个收款人，支持带引号的标签和带小数的金额。

## 本地复现

先在项目的 `web` 目录运行 `npm ci`。从项目根目录执行 `pwsh ./script/local-demo.ps1 -Port 18673`，可换用任意空闲端口。端口已被 Anvil 使用时，请换端口。只有在准备重置该本地链时才传入 `-Reset`。

回到 `web`，分别打开两个终端运行 `npm run dev` 和 `npm run local:watch`。访问 `http://127.0.0.1:5173/?local=1`，用公开测试账户连接链 ID 31337。钱包的 RPC 端口要与启动 Anvil 时使用的端口相同。监听器按区块和日志顺序处理规则变更及资产入账。需要单次处理时，先停掉监听器，再运行 `npm run local:process`。

用 **Demo USDC** 试分账、Aave 模拟储备和消费冷静期。用 **Wrapped ETH** 建好专用收款地址，保存并授权 WETH 规则，再向该地址发送本地 ETH。

## 部署配置

部署文件保留顶层 `token` 作为默认资产。配置多个资产时，为每个代币在 `assets` 数组添加 `id`、`token` 和 `label`。支持 Aave 的条目还需提供相同目标链上持有该资产储备的 `aavePool`。在共享 `modules.wrappedNative` 设置 WETH 地址。其他 `modules` 字段继续在同一部署内共用。旧的单资产配置依然支持，启用新的资产前应核实部署地址、代币精度及所用模块。

## 验收

| 场景 | 实际结果 |
| --- | --- |
| 一键本地部署 | 1,000 dUSDC 入账，分出 300、250、150，留存 300。重复处理无新增付款 |
| Aave 模拟储备暂时拒绝供给 | 初始分出 200，原凭证显示 400 排队。恢复供给并处理后，原凭证显示累计分出 600、留存 400 |
| 原生 ETH | 专用地址收到 1 ETH 并转出 WETH。20% 规则实付 0.2 WETH |
| 冷静期 | 100 dUSDC 锁定，等待期结束后释放 40，剩余 60 |
| 切换网络与资产 | 原钱包状态清除。浏览器用资产选择器切到 WETH 后，显示对应规则及原生 ETH 收款模块 |
