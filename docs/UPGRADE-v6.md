# PaydaySplit v6 — 累计预算目标、执行预演与方案备份

更新：2026-11-18。后续六维度完整规划见 [OPTIMIZATION-PLAN.md](OPTIMIZATION-PLAN.md)。

## 本次已实现

### 累计目标，避免固定账单反复全额支付

每个用户、代币、规则版本、桶分别保存 `BucketGoal(target, paid, cycle)`。成功付款才增加 paid，失败和被跳过的桶不增加。一次请求金额与目标剩余取较小值；该桶已达标时跳过，其他桶继续执行。

例如固定房租每笔 300、累计目标 350：三笔各 1000 的收入，房租依次支付 **300、50、0**；25% 税务仍每笔支付 250，15% 储蓄每笔支付 150。目标不是新的扣款授权，既有保留余额、单次/每日限制、暂停、到期和有限授权仍生效。

- 首次启用从零计数，不追溯之前付款。
- 修改目标保留已付进度；降低到已付以下会停止后续付款。
- 只有用户显式选择 **Start new cycle** 才归零并递增周期。**当前没有自动按自然月/发薪周期重置**。
- 目标为 0 时关闭封顶及进度记录，保留历史 paid；重新开启会继续已有进度，除非显式新周期。
- 目标按规则版本隔离。真实修改收款方/金额/比例/顺序/启用状态产生新版本，新版本无目标；完全相同的保存保留版本与进度。
- 设置目标必须传入预期规则版本，防止在过期页面误配另一组桶。目标变更立即作用于同版本待执行回调，不额外递增规则版本。

### 基于当前链上状态的执行预演

新增 `previewExecution(user, token, paycheck)`，输出各桶实付估算、保留金额及全局/用户暂停、到期、最低收入的阻断码；同时考虑目标、余额、授权、reserve、maxPerRun、dailyLimit 和当天支出。

它假设标准 ERC20 转账成功，不能预知黑名单、代币手续费、交易排序或未来状态。预演是读取时点估算；`retained` 是输入收入未分配额，不等于钱包总余额。旧 `previewWaterfall` 保留为不含目标和风控的基础数学预览。

### 方案 JSON 备份与恢复

备份包含桶标签/地址/金额/比例、目标草稿、支出控制和链/代币/精度。恢复检查大小、格式、金额、地址、总比例及当前网络，只复制白名单字段。导入只载入草稿，需分别保存去向、控制和目标。

备份不导入已付进度、授权、密钥或部署地址；无法用篡改 JSON 重置链上付款记录。当前导入要求同一网络、代币及精度，跨网络迁移需单独规划。

- 本地完整收入流程通过：Transfer → react → MockProxy → Split/Retained，见 `deployments/31337.evidence.json`。

复现：项目根目录 `pwsh ./script/local-demo.ps1`，再到 `web` 执行 `npm run local:goals`。仅使用可重置的本地 Anvil；运行会产生演示交易。测试说明见 [TESTING.md](TESTING.md)。

## 部署与限制

当前核心不可升级，v6 需要新部署并更新前端地址。旧地址没有目标和执行预演接口。迁移时暂停旧规则、撤旧授权，用户确认新规则后仅给新地址有限授权；不要让两套监听同时付款。

真实测试网、真实回调代理、自动周期、原生 ETH、跨链桥、生息和失败桶自动重试尚未完成。新界面经过 DOM 测试和构建，尚未完成人工浏览器视觉验收；现有截图/视频为历史 UI。没有独立安全审计。
