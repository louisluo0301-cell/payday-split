# PaydaySplit v5 — 用户控制与异常恢复

更新：2026-11-17。此文件是本次升级的验收入口。桌面原包保持原样，升级代码在当前工作区。

## 已实现

1. **钱包保留余额**：每次执行后仍为用户保留指定数量的 token。启用保留余额时，无法读取余额则不执行付款。
2. **单次支出与每日支出上限**：自动回调、手动付款、指定来源恢复共用每日累计。UTC 00:00 切日，修改规则或控制参数不会清空当天支出。按优先级分配剩余额度，最后一个可部分付款。
3. **最低收入、有效期、用户暂停**：目标链直接检查，可阻断排队中的回调。有效期到达即停止。参数为零表示不限制；保留余额为零表示不额外保留。
4. **按金额授权**：前端默认建议授权 1,000 token，可自行修改；调整已有授权先置零，再授权新金额；可随时撤销。合约不要求无限授权。
5. **指定来源恢复**：`recoverSplit(token, paycheck, originTxHash, logIndex)` 消费来源事件键，防止之后的自动回调重复付款。键包含用户与 token，另一用户无法抢占。金额由用户指定，只可使用调用者自己的授权资金，不提供来源真实性证明。
6. **单笔转账原子隔离**：自调用子交易内使用 SafeERC20，失败时同时回滚 token 状态。修复“转账后返回 false 但实际已经扣款”的边界。
7. **两步管理员交接**：目标链与 Reactive 侧均使用 Ownable2Step，候选管理员必须主动接受。
8. **费用运行检查**：`cd web; npm run health -- --local` 检查链、部署代码、绑定地址、双方原生币、双方欠费、回调次数额度、暂停。正式测试网用 `npm run health`。这是即时只读检查，不是后台监控服务。
9. **目标链偿债入口**：补足 callback 合约原生币后，owner 可执行 `coverDebt()`。转账充值本身不等同于偿债。
10. **演示模式同步升级**：BigInt 最小单位计算，支持控制参数与有限授权模拟，保留原始 bucket 索引；增加 DOM 交互回归测试。

## 操作示例

```solidity
// token 为 6 位小数：保留 200，单次最多 500，每日最多 1000，最低收入 10。
split.setPolicy(token, PaydaySplit.Policy(200e6, 500e6, 1000e6, 10e6, 0, false));
```

先保存 destinations，再单独保存 spending controls；链上确认后生效。界面顶部预览和 `previewWaterfall` 仅展示 bucket 数学，不包含余额、授权、控制参数或失败代币的影响。执行结果以事件与链上状态为准。

`New manual payment` 每次都会产生独立付款，不能当作同一笔收入的幂等重试。恢复遗漏收入请使用来源 hash + log index 的恢复入口。

## 部署与产品边界

- 这是需要重新部署的新版本；旧合约不可升级，旧地址不能直接获得新增功能。重新部署后更新前端 deployment JSON，并重新保存规则与控制参数。
- 控制参数拦截的自动回调会消费该事件；解除暂停不会补执行旧收入，必要时用户主动创建手动付款。
- 仅面向经过验证的标准 ERC-20 稳定币。手续费币、rebase、伪造余额/成功返回、耗尽 gas 的恶意 token 不受完整支持。保留余额不是对任意恶意 token 的资产保证。
- Reactive 仍需 lREACT，目标链回调仍需 ETH，应用层 remaining 次数不是原生币余额。过滤事件依然会消耗 react 执行费。
- 未添加收益策略、借贷、兑换或跨链桥。当前跨链的是控制消息，本金仍在同一目标链用户钱包中。
- 测试网部署、真实 Omni callback proxy 验证、外部代码审计、公开仓库/视频链接仍未完成。不能将本地证据写成测试网或主网成果。
- 发布前需实测真实代理 gas 预留、费用参数、长时间运行及多用户异常场景。不可将此包称为已审计主网产品。
